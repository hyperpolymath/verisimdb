== Octad: one entity, eight representations

[quote, README section "What VeriSimDB Does"]
____
Each entity exists simultaneously across up to 8 representations (the
octad) with automatic drift detection and self-normalisation.
____

*Evidence — eight modality crates:*

* `rust-core/verisim-graph/` — RDF + property graph storage (pure-Rust redb default, Oxigraph optional)
* `rust-core/verisim-vector/` — HNSW-based similarity search
* `rust-core/verisim-tensor/` — multi-dimensional array operations via Burn
* `rust-core/verisim-semantic/` — ontology + CBOR-proof type annotations
* `rust-core/verisim-document/` — full-text search via Tantivy
* `rust-core/verisim-temporal/` — versioning + time-series
* `rust-core/verisim-provenance/` — origin tracking, lineage chain, actor trail
* `rust-core/verisim-spatial/` — geospatial coordinates + R-tree proximity queries

*Evidence — unified entity abstraction:*

* `rust-core/verisim-octad/` — the one-ID-eight-stores layer that binds the
  modalities into a single `Octad` entity type.

*Reproduce:*

[source, sh]
----
$ find rust-core -name "Cargo.toml" -not -path "*/fuzz/*" | wc -l    # crate count
$ ls rust-core/verisim-{graph,vector,tensor,semantic,document,temporal,provenance,spatial}/Cargo.toml
----

== Drift detection

[quote, README section "What VeriSimDB Does"]
____
When VeriSimDB detects that an entity's vector embedding has diverged
from its document content, or that a provenance chain's hash integrity
is broken, or that spatial coordinates no longer match location
references in the text — it identifies the drift type, scores the
severity, and triggers repair automatically.
____

*Evidence — implementation:*

* `rust-core/verisim-drift/` — drift detector crate; cross-modal
  consistency monitoring with configurable severity thresholds.

*Evidence — formal model:*

* `formal/Drift.v` — Coq mechanisation of drift detection semantics +
  drift-type taxonomy.

The drift-type list (`semantic_vector_drift`, `graph_document_drift`,
`temporal_consistency_drift`, `tensor_drift`, `schema_drift`,
`quality_drift`) is documented in `.claude/CLAUDE.md` under "Drift
Detection".

== Self-normalisation

[quote, README section "What VeriSimDB Does"]
____
… and triggers repair automatically.
____

*Evidence — implementation:*

* `rust-core/verisim-normalizer/` — the repair engine. Identifies the
  most authoritative modality, regenerates drifted modalities from it,
  validates consistency, and updates all modalities atomically.

*Evidence — formal model:*

* `formal/Normalizer.v` — Coq mechanisation of the normalisation
  procedure + atomicity invariants.

== Query language (VCL)

[quote, README + .claude/CLAUDE.md]
____
VCL — VeriSim Query Language (native query interface, NOT SQL)
____

*Evidence — implementation:*

* `vql-bridge/` — VCL parser bridge (legacy name `VQL`, renamed
  2026-04-05; rename incomplete across the tree per
  `[[project_verisimdb_subject_of_everything]]`).
* `rust-core/verisim-planner/` — cost-based query planner with formally
  verified semantic equivalence (`formal/PlannerSemantic.v`,
  `formal/Planner.v`).
* `rust-core/verisim-repl/` — interactive VCL REPL.

*Evidence — formal model:*

* `formal/PlannerSemantic.v` — planner semantic-equivalence theorem
  (Q1-full, the foundation-pack query obligation).
* `formal/VCL.v` — VCL normalisation theorems (N2: normalise-idempotent;
  V2: vql-preservation).
