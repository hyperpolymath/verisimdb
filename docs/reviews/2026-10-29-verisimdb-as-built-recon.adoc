== 1. Independent purpose and vocabulary

VeriSimDB's research question is whether a lifecycle-managed *consonance
subject* remains the same subject, and under what authority and evidence, as
different representations change, disagree and federate. The intended
guarantee is stronger than "eight columns agree" or "the drift score fell".

The accepted terminology in \`docs/modality-profile.adoc\` and
\`vcl-ut/docs/decisions/0007-modality-profiles-vs-octad-schema.adoc\` is:

* *Consonance subject*: the lifecycle-managed identity.
* *Modality set*: the modalities populated for a subject at a time.
* *Modality profile*: the (normally versioned) supported/enabled selection
  and its constraints at a declared scope.
* *Octad*: this implementation's *fixed* eight-slot schema/API, not the
  generic word for arbitrary-arity subjects.

The current API does not exchange or negotiate profiles. \`OctadInput\`
supports seven optional payload modalities and a temporal slot populated by
the coordinator. A subject with only \`{document,temporal}\` is supported;
this is NOT variable-arity storage. A quandle/knot witness would require a
new, versioned modality-profile and capability contract, not a reinterpretation
of \`OctadSchema\`, VCLS v1 or a spare Octad slot.

See \`hyperpolymath/nextgen-databases/verisim-modular-experiment/\` for an
independent experimental implementation of a smaller core with external
federable witnesses. Its recorded parity checks are runtime tests, not an
arbitrary-cardinality production guarantee.

The Elixir KRaft metadata-log process does not establish consensus commits

\`verisimdb-data\` scans are not canonical Octad storage.

== 3. Conceptual E-R and physical data model

[source,text]
----
CONSONANCE_SUBJECT [OctadId; status, timestamps, version; in-memory]
   | 1:N                                  | 0:N
   +--> VERSION [entity_id, version,     +--> PROVENANCE_RECORD
   |             snapshot input/time]          [actor, source, event, hash,
   |                                          parent_hash, timestamp]
   | 0:1 currently present per modality
   +--> DOCUMENT [id, title, body, fields] -- Tantivy / document map
   +--> VECTOR [id, dimension, model, f32[]] -- redb / search cache
   +--> TENSOR [id, shape, f64[]]         -- redb / compute cache
   +--> SEMANTIC [id, types, properties]  -- redb / type+proof cache
   +--> SPATIAL [id, point/geometry, SRID] -- redb / linear scan cache
   +--> GRAPH_NODE [derived IRI]          -- not a separately durable node row
          | 0:N GRAPH_EDGE [subject,predicate,object]
          +--> GRAPH_EDGE -- redb triples, subject/object secondary indexes

WAL_ENTRY [sequence,entity_id,op,modality,payload,timestamp,CRC]
    -- segments on disk, used to reconstruct in-memory subject registry

FEDERATION_PEER [store_id,endpoint,modalities,trust,PSK hash]
    -- API process memory, not a foreign-key backed identity replica
----

This is a conceptual relation map, NOT a claim of an SQL schema or
referential constraints. Most canonical modality files are separate redb
databases; documents use Tantivy, and the subject registry itself is
rebuilt from the WAL when the persistent feature is enabled. A
cross-modality transaction is NOT a single physical database commit.
Indexes and in-memory read caches must be distinguished from durable
identities. See each \`rust-core/verisim-*/src/persistent.rs\` and graph
\`redb_backend.rs\`.

== 4. Eight-modality implementation/persistence matrix

[cols="1,3,3,3",options="header"]
|===
|Modality |Runtime implementation |Persistence with \`verisim-api/persistent\` |Important limit

|Graph |Graph edges; relationship traversal; simple graph and optional RDF backends |redb triples and subject/object indexes |Graph node synthesised from ID; deletion lacks delete-by-entity

|Vector |HNSW in default in-memory mode; embedding search |redb embeddings + rebuilt in-memory brute-force index |Similarity is real; embeddings are supplied or feature-hashed, not necessarily learned by a neural model

|Tensor |Shape-checked f64 arrays, map/reduce |redb + cache |Not a neural network; numeric tensor operations only

|Semantic |Type annotations, properties and proof-blob APIs |redb + caches |Stored proof blob does not by itself certify verifier acceptance or source authority

|Document |Tantivy full-text index/search, stored fields |persistent Tantivy directory + read map |A distinct storage engine; no physical global commit with redb

|Temporal |Version append, history and \`at_time\` |redb version histories + BTreeMap cache |Delta snapshot input omits unchanged prior values; historic reconstruction can be incomplete

|Provenance |Append and verify SHA-256 hash chain |redb chains + cache |Hash continuity != signed authenticity; no immutable external anchor shown

|Spatial |Coordinates, bounding/radius/nearest search |redb records + brute-force cache |Not an R-tree persistent spatial index
|===

Default \`verisim-api\` feature set is *in-memory*, not persistent.
The presence bitmap is populated per subject; \`temporal\` is appended on
every create/update and is absent from \`OctadInput\`. The \`require_complete\`
setting is declared but not enforced. Presence of all eight does not
establish independent, mutually agreeing witnesses.

== 5. Actual identity and state transitions

. \`POST /octads\`: API \`OctadRequest\` (flattened) converts to
  \`OctadInput\`. The coordinator generates an ID and logs intent, locks
  requested modalities, writes stores sequentially, appends a temporal
  version, updates the registry, then emits a commit marker.
. \`PUT /octads/{id}\`: currently *merge/update*, not replace. Omitted
  modalities remain populated; the temporal snapshot stores the supplied
  update input, not a complete materialized entity.
. Drift: \`drift_compute.rs\` inspects actual state where feasible and
  records aggregate observations best-effort. A component may be
  \`computable=false\`; missing evidence is not evidence of consonance.
. Normalisation: the API picks a target, the regeneration engine picks
  an eligible source by configured ranking and implements limited
  transformations: graph->document, document->vector via feature hashing,
  document/vector->tensor. It writes a "normalized" provenance event.
  Improved score is not a proof of authorised identity-preserving repair.
. \`DELETE /octads/{id}\`: removes registry entry and attempts vector,
  document and tensor deletions; leaves graph/semantic and other retained
  state/history. This is neither a proven tombstone model nor an authorised
  expungement operation.
. Federation: register peers with configured PSKs (disabled when absent),
  then query remote HTTP endpoints and aggregate results. A peer's
  \`trust_level\` initially equals 1.0, \`drifted=false\` is currently set
  in mapped results, and this endpoint is not a mutual witness proof.
. Recovery: pre-PR code mixed historical committed-entity flags with the
  last operation per entity; later interrupted writes could be reported
  as committed. PR #333 reconstructs only paired committed transitions
  and refuses ambiguous recovery. It does not undo partially persisted
  cross-modal writes or provide a power-loss proof.
. First-class merge/split, retraction, tombstone and authorised expungement
  are not demonstrated by the reviewed HTTP lifecycle endpoints. Do not
  advertise them as implemented on the basis of conceptual papers.

== 8. Independent Mathesis proof reuse programme

Mathesis itself is a *catalogue*; canonical proofs remain in their own repos.
Priority is determined by a *specific transport obligation*, not by theorem
count.

. *Immediate*: \`residual-evidence-types/Revision.agda\` provides
  assumption retraction and persistent refutation. Adapt to subject claims
  revoked after an upstream authority retraction; port and re-check under
  VeriSimDB assumptions.
. *Immediate*: \`vcl-ut\` accepted modality-profile ADR and concrete
  fixed-eight wire schema identify the current interface boundary.
. *High*: \`echo-types\` (canonical identity, projection and provenance
  fibres) for explaining what was forgotten in a projection.
. *High*: \`marches/Marches/Provenance.lean\` for graded path provenance
  through federation boundaries. Its own cross-repo Echo correspondence
  is explicitly *assumed*, not already ported.
. *High*: \`nextgen-databases/verisim-modular-experiment\` for a
  minimal-core/federation hypothesis and demonstrated runtime parity
  in limited cases. Its general non-interference proof remains open.
. *High*: \`januskey\` reversibility/transaction examples for explicitly
  authorised expungement/undo *specification*; its own proof debt and
  crash-persistence caveats prevent direct substitution.
. *Medium*: \`epistemic-types\`, \`trope-checker\` for graded epistemic
  confidence and evidence/representation fidelity.
. *Exploratory*: \`quandledb\` as a specialised external witness,
  \`absolute-zero\` and tropical models for resource/cost limits, not
  currently a provenance or crash-safety proof.

Proof transplant protocol: identify exact original statement and axioms;
write a bridge proposition for VeriSimDB's concrete types; check required
observations/authority/trust assumptions; port and prove; add runtime tests.
Never infer implementation soundness from a similarly named theorem.

== 9. Prioritised independent engineering programme

P0-a:: Review, pass CI and land #333 after considering old WAL histories,
  in-flight intents and rollback design. Fail closed is an interim safety
  measure, not durable atomicity.
P0-b:: Audit and gate HTTP/gRPC auth, expose secure deployment configuration,
  test RBAC across GraphQL and every mutation surface. #336 is one part.
P0-c:: Merge #334 only after clients are audited; publish the truthful
  versioned flattened request schema (or explicitly introduce nested v2).
P0-d:: Define deletion vs retraction vs tombstone vs expungement with
  retention, authorisation and provenance guarantees. Prohibit silent
  ungoverned destruction.
P1-a:: Implement a versioned lifecycle transition model, explicit VCL-UT
  enforcement modes, failure codes and signed evidence policy.
P1-b:: Repair temporal full-snapshot history and validate through crash
  boundaries; add multi-process persistent fault injection.
P1-c:: Require normalisation proposals, recorded source authority,
  independent evidence assessment, reviewer gates and reversal record.
P1-d:: Harden federation peer identities, evidence independence,
  trust/failure states, multi-node partitions and cache semantics.
P1-e:: Experiment with generic modality profiles *without* breaking
  existing fixed Octad or VCLS v1 contracts.
P2:: Benchmark spatial/vector indexing, memory/CPU, diagnostics
  accessibility, NIF implementation, deployment profiles and footprint.

The priority order is based on system integrity, not any specific
consumer. Hypatia is one downstream use case.

== 10. Safety and operational release gate

Before a production "persistent, federated identity-consistent" claim,
require: crash-injection recovery across every modality and WAL stage;
post-restart byte/identity/history comparisons; observed provenance
continuity; secure auth on every listener; explicit VCL transition
admissibility; evidence-aware normalisation; federation downgrade
handling; and a real profile/version compatibility matrix. No
destructive migration or automatic expungement is authorised by this
reconnaissance.
