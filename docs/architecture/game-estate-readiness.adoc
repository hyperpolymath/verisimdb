== Decision GE-001: keep the boundary optional and internal

VeriSimDB may hold derived authoring representations and provenance, while each
consumer owns its schema, source packages, reducer, replay and saves. No request
belongs on a simulation tick, frame-critical path or audio callback. Solo play
must work from game-owned prepared files with the service absent. UMS remains an
authoring/compiler tool. No game source or licence is imported by this change.

Keep exactly Graph, Vector, Tensor, Semantic, Document, Temporal, Provenance and
Spatial. Sparse subjects are normal; temporal history is automatic, not an input
modality. Start with Graph/Semantic/Document/Provenance plus generated Temporal.
Spatial needs a typed coordinate/reference model. Vector/Tensor require a use case.

Use the existing HTTP boundary and redb storage abstraction. Retire direct NIF
loading. Do not admit a SNIF kernel, Dragonfly, LMDB, Cap'n Proto or Bebop without
measurements. A SNIF is bounded pure compute with no I/O; Idris2 owns any ABI and
Zig implements any FFI. The external gateway belongs to unified-api-adapter.

The existing Octad write path does not yet meet the requested durable publication
contract. A later slice must either provide one atomic redb publication record
containing the selected coherent views/history, with disposable projections, or
implement genuine recoverable transactions spanning all stores. This decision
requires tests of interruption and visibility; the present TransactionManager
name is not evidence. Cross-request `/txn` operations must keep their explicit
501 response until actually implemented.

=== Failing identity/deletion reproducer — do not waive

`bash tests/tantivy-upgrade.sh` writes an index with Tantivy 0.26.1 and opens it
with 0.27.0. Stored id/title/body and text search round-trip successfully. The
subsequent deletion assertion FAILS: `upgrade-fixture` is still searchable after
`delete` and `commit`. `BASELINE_CONTROL=1 bash tests/tantivy-upgrade.sh` fails
the same assertion on 0.26.1 before the upgrade, establishing a pre-existing bug.
Both failures are retained and reproducible, not converted to expected success.

`DocumentSchema::new` indexes `id` as tokenised `TEXT`, while `index`/`delete`
delete an exact term containing the whole ID. Hyphenated IDs therefore do not
match their indexed tokens. A fix must preserve exact identifier semantics,
existing-index migration, update uniqueness and restart behaviour; simply
replacing `TEXT` with `STRING` makes old schemas incompatible. Persistent open
also reconstructs only id/title/body, dropping fields/metadata. This blocks
source-integrity and deletion claims for M2 even though existing tests pass.

`bash scripts/check-lock-sync.sh` verifies coverage, no orphan actions, transitive
closure and exact workflow keys. The official gh-actions-lock v0.4.0 online
verifier requires a CLI credential unavailable here. Its local verifier reports
job-level reusable references as stale even though the repository checker counts
them; neither observation is an online verification pass. GitHub setup remains
a required independent gate, including lockfiles owned by the called repository.

== Consumer contract and owner handoff (proposal; not an implemented endpoint)

The minimum versioned boundary must carry: contract version, consumer-owned
namespace/source identifier, a required durable idempotency key, expected current
revision, world/package revisions, source bytes and SHA-256 digest, schema
identifier/version, selected derived
views, transformation version, actor and correction authorisation. The service
must reject unknown versions, conflicting retries, stale revisions, oversized or
malformed inputs and cross-namespace access. Identical events must be idempotent.
Successful publication must identify one coherent durable revision and its digest.
The consumer supplies a key scoped to its namespace and stable across retries of
the same event; source identity and revision do not implicitly serve as the key.
The service must store the key and its request identity atomically with the
coherent publication record, returning that recorded outcome for identical
retries and rejecting reuse with different inputs. After an unknown outcome,
clients must reconcile using the same key before issuing a new event.

Read/history must return the same source identity, revision and digest. Drift is
reported with expected/observed evidence; it must not rewrite canonical game
content. Correction is an explicit authorised new version with an audit trail,
or an explicit rejection. Rebuild derives indexes from preserved authoritative
inputs/history. A timeout is an unknown publication outcome until resolved by
idempotency key; clients must not blindly issue a new event.

IDApTIK's scenario semantics and Slavia Zone A's quickening, settling, living-world
response and place memory stay consumer-owned. Standard Operating Psychopathy's
needs/resources/infrastructure form a later distinct fixture. No external game
fixture has yet been imported or certified by this change. A local fixture must
be labelled synthetic and cannot stand in for game integration acceptance.

Owner gates:

* VeriSimDB: correct publication/recovery and strict wire mapping; durable fixture,
  replay/idempotency, adversarial auth and resource-budget evidence.
* Game/Enaction/UMS owners: fixtures with licence/provenance, schema mappings,
  expected revisions, correction policy, optional prepared-file fallback.
* unified-api-adapter owner: initialise the service; authentication, namespace
  authorisation, TLS, budgets/audit; preserve error and idempotency semantics.
* Verification owner: checked Creusot contracts and Idris2/Zig obligations when an
  ABI is admitted. No Rust/C FFI alternate specification.
* Benchmark owner: small/medium/large, cold/warm, p50/p95/p99, failures, hardware,
  memory/disk/write amplification, startup/shutdown, cancellation/unavailable
  service; compare source files/redb and actual Octad. Cache tests must include a
  workload that loses. No speed ranking is justified by this audit.
